# Next.js 16.3 — delta cheat sheet (vs. Next 14/15 habits)

Verified against the bundled docs in `node_modules/next/dist/docs/01-app/` (paths cited per item).
Project state: `next 16.3.0`, React 19.2, Turbopack, **`cacheComponents` is NOT enabled** in
`next.config.ts` → the "previous" caching model applies here (see §4).

## 1. `params` / `searchParams` are Promises — sync access is REMOVED

Doc: `02-guides/upgrading/version-16.md` §"Async Request APIs (Breaking change)", `03-api-reference/03-file-conventions/page.md`.

- Next 14: `params.slug` directly. Next 15: sync access warned. **Next 16: only async.**
- Applies to `params` in page/layout/route/default/opengraph-image/icon, and `searchParams` in page.

Repo's proven pattern (`app/uiworkshop/(shell)/view/[slug]/page.tsx`, `.../flow/[id]/page.tsx`):

```tsx
export default async function ViewPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  // ...
}
```

In a **client** page component, unwrap with React's `use()` (page.md §searchParams):

```tsx
'use client'
import { use } from 'react'
export default function Page({ searchParams }: { searchParams: Promise<Record<string, string | string[] | undefined>> }) {
  const filters = use(searchParams).filters
}
```

### Generated type helpers: `PageProps<>`, `LayoutProps<>`, `RouteContext<>`

Docs: `page.md` §"Page Props Helper", `layout.md` §"Layout Props Helper", `route.md` §"Route Context Helper".

- **Globally available** (no import) after type generation; generated by `next dev`, `next build`, or `next typegen` into `.next/types/routes.d.ts` (this repo already has it).
- Keyed by the **route literal**: `PageProps<'/blog/[slug]'>` → `params: Promise<{ slug: string }>` + `searchParams: Promise<...>`. Static routes resolve `params` to `{}`.
- `app/layout.tsx` here uses `LayoutProps<"/">` — that is this convention: `{ params: Promise<{}>; children: React.ReactNode }` plus typed parallel-route slots.
- Either style is fine; the repo uses inline `Promise<{...}>` for pages and `LayoutProps` for the root layout. Route literal must exist in `ParamMap` or it's a type error.

## 2. Server Actions ("Server Functions")

Doc: `01-getting-started/07-mutating-data.md`.

Unchanged mechanics from 15, but terminology is "Server Functions"; "Server Action" = one used in an action context. Still `'use server'` at top of async function (Server Component inline) or top of a file; import into Client Components (cannot be *defined* there). Invoked via `<form action={fn}>`, `formAction`, or event handlers + `useActionState`. Always auth-check inside — they're reachable by direct POST.

```ts
// app/lib/actions.ts
'use server'
export async function createPost(formData: FormData) { /* verify auth, mutate, revalidate */ }
```

New action-side cache APIs (see §4): `updateTag(tag)` (read-your-writes, actions only), `refresh()` from `next/cache` (refresh client router from an action). Doc: `02-guides/upgrading/version-16.md` §"Caching APIs".

## 3. Route Handlers

Doc: `01-getting-started/15-route-handlers.md`, `03-api-reference/03-file-conventions/route.md`.

- Same `app/**/route.ts` with `GET/POST/...(request: NextRequest | Request, ctx)` — but `ctx.params` is a **Promise**, and there's a generated global helper:

```ts
export async function GET(_req: NextRequest, ctx: RouteContext<'/users/[id]'>) {
  const { id } = await ctx.params
  return Response.json({ id })
}
```

- **Not cached by default** (GET included). Opt in with `export const dynamic = 'force-static'` (only meaningful without cacheComponents).
- `runtime = 'edge'` is **deprecated** (`03-file-conventions/02-route-segment-config/index.md`): only `'nodejs'` going forward.

## 4. Caching model — THIS PROJECT (no `cacheComponents`): "previous model"

Doc: `02-guides/caching-without-cache-components.md`.

- `fetch` is **uncached by default**; opt in per request with `{ cache: 'force-cache' }` or `next: { revalidate, tags }`.
- Non-fetch data: `unstable_cache(fn, keys, { tags, revalidate })` (still `unstable_`).
- Segment config still works here: `export const dynamic = 'auto' | 'force-dynamic' | 'error' | 'force-static'`, `fetchCache`, `revalidate`.
- Pages with no dynamic API and no uncached data are **statically prerendered at build**. Reading `cookies()`/`headers()`/`searchParams` makes the route dynamic (rendered per request).
- **Viewer-dependent responses must not be cached**: never `force-static` on such routes; when in doubt `export const dynamic = 'force-dynamic'` on the page/handler, or just read `cookies()`/`headers()` — that alone opts the route out of prerendering in this model.
- `revalidateTag(tag)` now takes a **required second argument** (profile): `revalidateTag('posts', 'max')` — single-arg form is deprecated and a TS error (`version-16.md` §revalidateTag). `revalidatePath` unchanged. `unstable_noStore` → use `connection()` instead (`04-functions/unstable_noStore.md`).

### If `cacheComponents: true` is ever enabled (doc: `01-getting-started/08-caching.md`, `05-config/01-next-config-js/cacheComponents.md`)

The model inverts to Cache Components + PPR-by-default:

- Segment configs `dynamic`, `revalidate`, `fetchCache`, `dynamicParams` are **removed**; `experimental_ppr` removed.
- Caching is via directives: `'use cache'` at top of an async function/component/page/file, paired with `cacheLife('seconds'|'minutes'|'hours'|'days'|'weeks'|'max'|custom)` and `cacheTag(tag)` (both **stable**, no `unstable_` prefix — import from `next/cache`).
- Anything uncached or reading runtime APIs (`cookies()`, `headers()`, `params`, `searchParams`) must sit **inside `<Suspense>`** or the build/dev overlay flags it (blocking-route error).
- `'use cache'` scopes **cannot** touch `cookies()`/`headers()`/`searchParams` (even via helpers) — extract the value outside and pass it as an argument (it becomes part of the cache key). Variants: `'use cache: private'` (may read runtime data, cached only in the browser), `'use cache: remote'` (durable shared handler). Dir: `03-api-reference/01-directives/`.
- Random/time values need `await connection()` (per-request) or `await io()` (new in `04-functions/io.md`) before `Date.now()`/`Math.random()` inside Suspense — or `'use cache'` to freeze them.
- Requires Node.js runtime; `runtime = 'edge'` routes must migrate first.

## 5. `cookies()` / `headers()` / `draftMode()` — async only

Docs: `04-functions/cookies.md`, `04-functions/headers.md`.

```ts
const cookieStore = await cookies()   // read in Server Components; read/write in Server Functions & Route Handlers
const ua = (await headers()).get('user-agent')  // read-only
```

The Next-15 sync compatibility shim is **gone** in 16. Reading either makes the route dynamic (in this project's model) — which is what we want for viewer-dependent output.

## 6. Middleware is now `proxy.ts`

Docs: `03-file-conventions/proxy.md`, `03-file-conventions/middleware.md` (deprecation stub), `01-getting-started/16-proxy.md`.

- File: **`proxy.ts` at project root** (not `middleware.ts`, not inside `app/`). Export default or a function named `proxy` (not `middleware`).
- Runtime is **Node.js and not configurable** (edge NOT supported in proxy; keep `middleware.ts` only if you truly need edge, but it's deprecated).
- `config.matcher` works exactly as before (strings, regex, `has`/`missing`). Without a matcher it runs on every request including `_next/static` — use a negative pattern.
- Config renames: `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`, etc. Codemod: `npx @next/codemod@canary middleware-to-proxy .`

```ts
// proxy.ts
import { NextResponse, type NextRequest } from 'next/server'
export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/home', request.url))
}
export const config = { matcher: ['/((?!api|_next/static|_next/image|.*\\.png$).*)'] }
```

## 7. `next/dynamic` with `ssr: false`

Doc: `02-guides/lazy-loading.md`.

Unchanged from 15: `ssr: false` **only inside Client Components** ("`'use client'`" files) — using it in a Server Component is an error. Move the `dynamic(() => import(...), { ssr: false })` call into a client wrapper component.

## 8. error.tsx — `reset` renamed to `retry` (16.3 stable)

Doc: `03-file-conventions/error.md` (version history: `v16.2` `unstable_retry`, `v16.3` `retry` stable).

```tsx
'use client' // error boundaries must be Client Components
export default function Error({ error, retry }: { error: Error & { digest?: string }; retry: () => void }) {
  return <button onClick={() => retry()}>Try again</button>
}
```

- Writing `reset` (the 14/15 prop name) gets you `undefined`. `global-error.tsx` still must render its own `<html>/<body>`.
- New: `catchError(Fallback)` from `next/error` for **component-level** boundaries (`01-getting-started/10-error-handling.md` §catchError) — fallback receives `(props, { error, retry })`.
- `notFound()` + `not-found.tsx` unchanged (repo already uses `notFound()` in `view/[slug]/page.tsx`). `redirect`/`permanentRedirect` unchanged.

## 9. Other surprises (version-16.md unless noted)

- **Turbopack is the default** for `next dev` AND `next build`. A custom `webpack` config makes `next build` **fail**; opt out with `--webpack`, or in with `--turbopack`. Turbopack config is top-level `turbopack: {}` in next.config, not `experimental.turbo`.
- **`next dev` outputs to `.next/dev`** (separate from build output; lockfile prevents concurrent instances).
- **Parallel route slots require explicit `default.tsx`** — build fails without them (`return null` or `notFound()`).
- **`next lint` removed**; `next build` no longer lints. `eslint` key in next.config removed.
- Removed: AMP, `serverRuntimeConfig`/`publicRuntimeConfig` (use env vars; `NEXT_PUBLIC_` for client), `experimental.dynamicIO`/`experimental.useCache` (→ `cacheComponents`), `unstable_rootParams` (→ `next/root-params` module: `import { lang } from 'next/root-params'`).
- **Images**: `minimumCacheTTL` default 60s → **4 hours**; `qualities` default now **`[75]`** (other `quality` values error unless configured); `16` removed from `imageSizes`; local images with query strings ignore the query unless `images.localPatterns.search` configured; private-IP sources blocked; `images.domains` deprecated → `remotePatterns`; `next/legacy/image` deprecated.
- **Scroll**: Next no longer overrides `scroll-behavior: smooth` on navigation; add `data-scroll-behavior="smooth"` on `<html>` to restore old behavior.
- **opengraph-image / icon / sitemap generators**: `params` and `id` args are now Promises too — `await params`, `await id`.
- **Minimums**: Node.js 20.9+, TypeScript 5.1+.
- Fonts (`next/font/google` — Geist etc.) and `generateMetadata`/`metadata` export: no breaking changes; but `generateMetadata` `params` is a Promise like everywhere else.
- **AGENTS.md block** is auto-written by `next dev` via `node_modules/next/dist/server/lib/generate-agent-files.js` (doc: `02-guides/ai-agents.md`). Don't fight it — commit it; the bundled docs at `node_modules/next/dist/docs/` always match the installed version.

## 10. next.config.ts / production / self-hosting

Docs: `05-config/01-next-config-js/`, `02-guides/self-hosting.md`.

- `next.config.ts` (TypeScript) is first-class; this repo uses it (`allowedDevOrigins` for cross-origin dev asset access — a 16 addition).
- Relevant prod options: `cacheComponents`, `output: 'standalone'` (`.next/standalone` + `server.js`, deployable without node_modules), `cacheHandlers`, `expireTime`, `reactCompiler` (stable, off by default), `partialPrefetching`, `turbopackFileSystemCache`.
- Self-hosting with `next start`: image optimization, proxy, ISR/caching work with zero config on a single instance with persistent disk; multi-instance needs a shared cache handler + `generateBuildId`/`deploymentId` alignment. `after()` fully supported. `NEXT_MANUAL_SIG_HANDLE=true` for manual graceful shutdown.
- `next build` output no longer prints `size` / `First Load JS` metrics.

## TL;DR for this repo

1. Copy the existing pattern: `async function Page({ params }: { params: Promise<{ x: string }> })` then `await params`; `LayoutProps<'/route'>` for layouts; `notFound()` for unknown slugs; `generateStaticParams()` where the set is known.
2. `await cookies()` / `await headers()` always; anything viewer-dependent: read a request API or set `export const dynamic = 'force-dynamic'` — never `force-static`, never `fetch` with `force-cache` on personalized data.
3. Error boundary prop is `retry`, not `reset`.
4. Middleware goes in root `proxy.ts` with `export function proxy(...)`.
5. Don't add `'use cache'` / `cacheLife` / `cacheTag` — they require `cacheComponents: true`, which this project doesn't enable.
